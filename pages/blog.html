Project blog

Development diary for the Study Task Manager, written while building the application.

Three week Agile sprint plan

The project was delivered in three one week sprints. Each sprint finished with something that could be opened in a browser, which made it easier to spot problems early.

Agile sprint plan mapped to the system development life cycle
Sprint Phase Activities Deliverable
Week 1 Planning and analysis Wrote the list of required pages, reviewed the assignment brief and drew the task data model (title, course, due date, description, notes). Page skeleton and agreed feature list
Week 1 Design Chose a colour palette, a two column hero layout and a table layout for the task list. Sketched the login gate and the add task form. Written layout plan and stylesheet structure
Week 2 Implementation Built the home page and image switcher, then the task form, the table and local storage persistence. Working task manager with add and delete
Week 2 Implementation Added edit mode, validation messages and the overdue / due soon status labels. Complete create, read, update and delete features
Week 3 Testing and maintenance Tested invalid dates, empty fields, deleting a task that does not exist and reloading the page. Fixed the two bugs described below and re-tested in Chrome and Edge. Final website, README and this blog

Development errors and how I fixed them

Each entry records what went wrong, the faulty code, and the change that fixed it.

Error 1: impossible dates were accepted by the validator

Found on 9 November 2026, around 21:40, while testing the due date field.

Typing or scripting a date such as 2026-02-31 was accepted. JavaScript's Date object silently rolls an impossible day forward into the next month, so the check passed even though the user never picked a real date. 

var parsed = new Date(values.dueDate);

// NaN is the only case this catches, so 2026-02-31 still passes.
if (isNaN(parsed.getTime())) {
  errors.push("Due date is not a valid date.");
}

Cause: new Date("2026-02-31") produces 3 March 2026 instead of an invalid date, so a simple isNaN test is not enough.

Fix: build the date from its parts and compare the parts back again.

var parts = values.dueDate.split("-");
var year = Number(parts[0]);
var month = Number(parts[1]);
var day = Number(parts[2]);
var parsed = new Date(year, month - 1, day);

var isRealDate =
  parsed.getFullYear() === year &&
  parsed.getMonth() === month - 1 &&
  parsed.getDate() === day;

if (!isRealDate) {
  errors.push("Due date is not a real calendar date.");
}

Console output while the bug was present:

// Testing 2026-02-31 in the due date field
date value: "2026-02-31"
new Date("2026-02-31") -> Tue Mar 03 2026 00:00:00 GMT+1030
validation result: accepted (no errors)

Error 2: the delete button did nothing at all

Found on 10 November 2026, around 19:15, after adding the delete feature.

Clicking Delete did not open the confirmation dialog and no error appeared on screen. The console reported that deleteTask was not defined. 

// Inside the render loop
row.innerHTML =
  "<td>" + task.title + "</td>" +
  "<td><button onclick='deleteTask(" + task.id + ")'>Delete</button></td>";

Cause: the code ran inside an immediately invoked function, so deleteTask was not a global function and the inline onclick attribute could not see it.

Fix: create the button, then attach the listener with addEventListener so it keeps access to the function's scope.

var deleteButton = row.querySelector('[data-action="delete"]');

deleteButton.addEventListener("click", function () {
  deleteTask(task.id);
});

Console output while the bug was present:

Uncaught ReferenceError: deleteTask is not defined
    at HTMLButtonElement.onclick (tasks.html:1:1)

What I would do differently

Testing each feature as soon as it was finished would have caught both bugs earlier. The date bug in particular would never have appeared if I had tested one impossible date before moving on.
